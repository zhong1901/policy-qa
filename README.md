# 上海人才政策问答助手

> 一个能**点回原文**的上海落户 / 人才政策问答系统。
> 每条结论都挂条款编号，资料里没有的它直接说没找到，**不猜**。

**在线演示** → https://policy-qa.onrender.com （访问口令：`shanghai2026`）
**资格自测** → https://policy-qa.onrender.com/check.html

> ⚠️ 个人学习作品，与上海市人力资源和社会保障局无隶属关系。
> 免费实例 15 分钟无访问会休眠，首次打开可能等 30–60 秒。

---

## 它解决什么问题

我自己是应届生，想在上海落户。查的时候遇到三件事：

1. 百度前三页全是中介广告；
2. 人社局网站上的文件是 PDF，而且同一部办法有 2020 版、2024 版好几个版本，看不出哪个是现行的；
3. 问 ChatGPT，它答得很像，但**引用的是已经废止的条款**——而我根本发现不了。

所以做了这个系统。它的核心不是"答得多好"，而是**答错了你能发现**：

- 每个结论句后面有 `[C1]` 这样的角标，点开能看到条款原文和前后条
- 引用的文字必须**逐字**来自原文，改写过的会被校验拦下
- 资料里没有的，返回「未找到明确的政策依据」，而不是编一个

## 核心设计

### 一、为什么不用 512 token 切块

通用 RAG 的标配是定长切块，但**在这个场景是错的**。

公文里一个条款常有几百字，还有「（一）（二）（三）」分项。按字数切下去，很容易把「第（三）项」切到下一个块里，**引用时就指错了**——用户点开看到的是半句话。

所以改成**按条号连续性切分**：

```
真正的条款边界必然满足 第一条 → 第二条 → 第三条 递增
但正文里有「本办法第五条规定……」这种引用，会让序号跳变
→ 把中文数字转整数，只接受「等于期望序号」的那一个
```

另外两个坑也处理了：

- **第一条被吞进前言**：前面是标题不是句号，规则匹配不到 → 用条号递增判断
- **一个文件含两部办法**：条号会从 15 回到 1 → 检测到「序号=1 且上一条≥2」就开新段

### 二、四道防幻觉闸

```
① Prompt 强制角标      每个结论句必须带 [C1]
        ↓
② 引用反查             抽出的编号必须在本次召回的 5 条里
        ↓
③ 引文逐字比对         与原文的最长公共子串含量 < 90% 判定为「改写了条文」
        ↓
④ 带问题重试           仍失败 → 降级成拒答
```

判不了的会**明说**，而不是给一个"看起来对"的答案。

### 三、混合检索

```
提问
 ├─ 语义路：bge-m3 向量化 → pgvector HNSW 近邻 → 30 条
 └─ 关键词路：2 字 bigram → ILIKE 匹配 → 30 条
        ↓
   RRF 融合（按名次算分，两路都命中得分更高）
        ↓
   取前 5 条 → 喂给大模型
```

**为什么两路都要：**

- 纯向量怕数字和专名——用户问「第 5 条」「沪府规〔2024〕17 号」时向量不敏感
- 纯关键词怕说法不一致——用户说「居转户」，公文写的是「持证人员申办本市常住户口」，**字面完全对不上**

### 四、跨版本召回

「2024 版和 2020 版有什么不同」这类问题，普通检索注定只答一半——时间过滤会把已失效的旧版本排掉。

所以单独开一条通道：

```
① 从问题里认出政策族（居转户 / 引进人才 / 居住证积分 …）
② 按 policy_family 字段找到该族所有版本
③ 取同一个条号，各版本并排返回
```

难点是**合订本**：2025 年那份文件把《引进人才申办办法》和《持证人员申办办法》印在同一个文件里。按文档找族会把两部办法的条款混在一起。

解法是把族标签下沉到**条款级**（`clauses.policy_family`），合订本按 `segment` 分段判定。

### 五、资格自测：规则 + 检索分工

| 层 | 负责 | 为什么 |
|---|---|---|
| **规则层** | 算得准（居住证满 7 年、社保满 84 月…） | 硬条件交给模型会引入不确定性 |
| **条款层** | 说得清（每条结论绑真实 clause_id） | 判定完把原文取出来一起返回 |

比如积分里「学历与职称二选一取高」，是读条款读出来的——原文写着「两项指标选择一项进行积分」。

## 踩坑记录

这部分比功能列表更有价值。每个都是**看起来对、实际错**的类型。

### 1. 加了个「合理」的排序，召回率从 93% 崩到 61.7%

给关键词检索加 `ORDER BY 命中词数 DESC`，逻辑上完全说得通——命中越多越相关。

**实际结果是长条款霸榜**：长文本天然命中更多 bigram，精确的短条款被挤出候选。

`Recall@5` 从 93.3% 掉到 61.7%。**没有评测集，这个退化根本发现不了**——系统照样跑、照样出答案、引用还都是真的，只是答案变差了。

### 2. 引用精确率 63.8%，查了两天才发现是指标错了

「引用精确率」定义是「引用中有多少是标注条款」，隐含假设**每题只有一个正确答案**。

但一条答案合理引用 3 条（结论一条、条件一条、流程一条），只有 1 条被标注 → 精确率只有 33%。**这不是引错，是引全了。**

换成「引用命中率」（是否包含标注那一条）之后是 100%。

> 教训：**指标选错会制造假问题。**

### 3. 拿失效文件出题，还怪系统答不出来

加了 3 道题，系统全答不上来，我以为检索坏了。

查下来：那 3 题的 gold 出自《上海市事业单位聘用合同管理办法》，**这办法 2023 年底就失效了**。系统把它过滤掉是**正确行为**，错的是我出题时没核对有效期。

后来写了个体检脚本，把全部 gold 做有效期扫描，撤回那 3 题。

> 教训：**评测集的 bug 会伪装成系统的 bug。**

### 4. pgvector 的 ef_search 默认只有 40，静默漏条款

同一个查询，`LIMIT 30` 完全找不到的条款，`LIMIT 400` 排第 2。

根因：HNSW 是近似检索，`ef_search=40` 意味着"只探 40 个候选就收工"。

```python
async with conn.transaction():
    await conn.execute("SET LOCAL hnsw.ef_search = 200")
    rows = await conn.fetch(_VECTOR_SQL, ...)
```

**它不报错、不告警，只是悄悄少返回一些本该返回的条款。** 只在候选池里相似条款很多时才明显。

### 5. 关键词路的 LIMIT 截断，让指标取决于磁盘排列顺序

```sql
WHERE content ILIKE ANY(...) LIMIT 120   -- 没有 ORDER BY
```

一次查询常匹配 4000+ 条，只取 120 条（3%），而且是**物理顺序的前 120 条**。

后果：

- 正确答案可能是全局第 2 名，却连候选池都进不去
- 数据被更新过（行被重写）后，这 120 条的组成就变了 —— **同一个查询指标会变**

实测：某次给表加字段后，`Recall@5` 从 93.3% 变成 82.5%，代码一行没改。

**试过三种修法全失败**（放开截断 74.6%、长度归一化 74.6%、同义词扩展无变化），目前作为已知限制留着。

### 6. SSE 第一个事件等了 8.4 秒

FastAPI 的 `@app.middleware("http")` 底层是 Starlette 的 `BaseHTTPMiddleware`，它会把整个响应体包一层——**流式响应被攒住了**。

改成纯 ASGI 中间件（自己写 `__call__`、包装 `send`）后，第一个事件降到 1.6 秒。

> 加了流式接口，中间件却还在按一次性响应工作。

### 7. CI 连挂四轮，每轮一个真 bug

| 轮次 | 现象 | 根因 |
|---|---|---|
| 1 | 绿勾，但指标全错 | `cmd \| tee` 返回 tee 的退出码（永远 0），脚本失败被吞 |
| 2 | 同样 | GitHub 的 `Re-run` **复用旧配置**，不读新文件 |
| 3 | `ask() missing 'request'` | 加埋点时给函数加了必填参数，评测直接调用就崩 |
| 4 | `URL 缺少协议头` | workflow 里写了 `${{ secrets.X }}` 但没建 → 空串覆盖默认地址 |
| 5 | `Recall 0.0%` | 本地时间当 UTC 下界，SQL 把所有记录都排除了 |

**第 3 轮顺带发现一个线上 bug**：`ask_stream` 用了 `request` 却没声明参数——**线上流式接口本来就是坏的**，前端用的正是这个。

> 一个不会失败的检查，等于没有检查。

## 已知限制

诚实列在这，不藏着：

| 限制 | 具体情况 |
|---|---|
| **版本时效 60%** | 跨版本召回只做了一半，多版本对比还不够稳 |

| 数据覆盖 | 只有上海人社 + 市政府两个来源，不含区级政策 |
| 图解类页面 | 「一图了解…」正文在图片里，当前跳过（无 OCR） |

## 技术栈

```
语言框架    Python 3.12 · FastAPI（async）· Pydantic v2 · asyncpg（手写 SQL，不用 ORM）

```

## 本地运行

```bash
# 1. 依赖
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 2. 配置（复制模板后填值）
copy .env.example .env

# 3. 建表
python scripts/ensure_tables.py

# 4. 启动
uvicorn app.main:app --host 127.0.0.1 --port 8123
```

打开 http://127.0.0.1:8123 ，输入 `.env` 里配置的访问口令。

**必需的环境变量：**

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | PostgreSQL 连接串（需启用 pgvector 扩展） |
| `LLM_API_KEY` | 生成用模型 key |
| `EMBEDDING_API_KEY` | 向量化 key |
| `ACCESS_CODE` | 访问口令（留空则不校验） |
| `STATS_KEY` | 统计页口令（留空则统计页 404） |

## 评测集

69 道题，人工标注，四层分布：

```
eval/qa_eval.csv      题目、预期答案、gold 条款 id
eval/eval_report.json 最近一次评测的逐题明细
```

跑评测：

```bash
python scripts/run_eval.py --temperature 0 --sleep 1.5
python scripts/run_regression.py            # 和基线对比，退化退出码 1
python scripts/run_regression.py --save 标签  # 存新基线
```

**关于噪声**：实测即使 `temperature=0`，同一份数据跑两次，12 道拒答题里仍有 2 道行为不同（16.7%）。所以回归阈值是按噪声定的，不是拍的。
